|---|---|

## 1. In scope

| Area | Included |
|---|---|
| Settings shapes | Flat fields, `env_prefix`, aliases, `SecretStr` |
| Files | `.env.example` (regenerated), `.env` (merged) |
| Interfaces | CLI (`sync`, `check`), Python API (`sync_env`, `env_sync_on_init=True` on boot) |
| CI / hooks | `check` exits non-zero on drift (usable as pre-commit or CI step) |
| AI angle | Annotated `.env.example` as the agent-readable schema |
| Packaging | `src/` layout, `pyproject.toml`, pytest suite |

## 2. Out of scope

- Nested models (`env_nested_delimiter`, e.g. `DB__HOST`)
- Multiple Settings classes or non-env sources (yaml, toml, secrets dir)
- `.env.test` / `.env.prod` and other variants
- Machine-readable schema file; agent-config snippets (`CLAUDE.md`, ignore rules)
- A dedicated pre-commit package (users call `check` directly)
- CLI frameworks (`typer`, `click`)
- `python -m <name>` entry point (`__main__.py`), `EnvManagedSettings` class-method sugar (`Settings.sync()` / `.check()`), and `"module:Class"` strings in `sync_env` (deferred; the Python API and the CLI script already cover v1)

## 3. Functional requirements

### 3.1 Key resolution
- Env var name = `env_prefix` + (`validation_alias` or field name), uppercased unless `case_sensitive=True`.
- `AliasChoices`: first choice is used. `AliasPath`: field is skipped with a warning.
- One shared function resolves names for both files.

### 3.2 `.env.example` generation
- File is fully owned by the tool and rewritten deterministically (field declaration order).
- Each variable is rendered as an annotation comment plus a `KEY=value` line:
  ```
  # PORT (int, default: 8000) - HTTP port
  PORT=8000
  ```
- Value rules:
  - Field with a default → default rendered.
  - Required field → blank value, `required` in the comment.
  - `SecretStr` → always blank.
- Description is taken from `Field(description=...)` when present.
- Keys that no longer exist in Settings are dropped.

### 3.3 `.env` merge
- Existing keys: value, inline comments and order are preserved untouched.
- Missing keys are appended:
  - default exists → default value;
  - no default → blank `KEY=` with a `# REQUIRED` marker;
  - `SecretStr` → always blank.
- Keys not defined in Settings are moved to the end of the file under the heading comment `# Your additional env variables`, together with their preceding comments.
- Nothing is deleted; no existing value is overwritten.
- Lines the tool does not touch are written back unchanged.

### 3.4 CLI
```bash
pydantic-env-manager sync  <module:Class> [--env .env] [--example .env.example]
pydantic-env-manager check <module:Class> [--env .env] [--example .env.example]
```
- `<module:Class>` is an import path to the Settings class.
- `sync` writes both files.
- `check` writes nothing and exits `1` when:
  - `.env.example` differs from what would be generated, or
  - `.env` is missing keys.
  Extra keys in `.env` are reported but do not fail the check. A `.env` that does not exist is skipped (CI has none). Exit `0` otherwise.
- `--env` defaults to the class's `model_config["env_file"]`, else `.env`; `--example` defaults to `.env.example` next to it.

### 3.5 Python API and boot sync
```python
sync_env(Settings, env_file=".env", example_file=".env.example")
```
- Subclass `EnvManagedSettings` and set `env_sync_on_init = True` to sync when the Settings object is created. Paths follow the same defaults as the CLI.
- Env keys with an alias are used as-is: `pydantic-settings` does not apply `env_prefix` to aliased fields.
- Skipped when `CI` or `PROD` is set in the environment.
- A write failure logs a warning and never raises into the application.

## 4. Non-functional requirements

| Requirement | Detail |
|---|---|
| Safety | Never delete or overwrite `.env` content; never write secret values |
| Idempotency | A second run produces no changes; unchanged files are not rewritten |
| Atomicity | Writes go to a temp file and are renamed into place |
| Dependencies | `pydantic-settings` ≥ 2 only |
| Compatibility | Python ≥ 3.9, Pydantic v2 |

## 5. Module layout

```
src/<name>/
  __init__.py   # re-exports the public API
  sync.py       # sync_env, check_env, EnvManagedSettings (boot hook), atomic writes
  schema.py     # Settings → [VarSpec(key, type, default, required, secret, description)]
  envfile.py    # line-preserving .env parser and merger
  render.py     # .env.example generator
  cli.py        # argparse: sync, check
tests/
docs/
pyproject.toml
```

## 6. Acceptance criteria / test plan

- [ ] Prefix and alias resolve to the correct env var names (incl. `case_sensitive`)
- [ ] `AliasChoices` uses the first choice; `AliasPath` is skipped with a warning
- [ ] `SecretStr` is blank in both files
- [ ] Required fields render as blank with the right marker; defaults render correctly
- [ ] `.env` merge preserves existing values, comments and order
- [ ] Missing keys are appended; extras are moved under `# Your additional env variables`
- [ ] Quoted and `export KEY=` lines are handled; multi-line quoted values stay intact
- [ ] Running sync twice is a no-op (idempotent)
- [ ] `.env.example` drops stale keys
- [ ] `check` exits `1` on example drift or missing `.env` keys, `0` otherwise; writes nothing
- [ ] `env_sync_on_init=True` writes both files; skipped under `CI` / `PROD`; write failure only warns
